This page is for someone reviewing `https://mcp.lunacal.ai/mcp` before they let an assistant use a Lunacal account. The user-facing setup is on [MCP server](/mcp-server).

There are two hops. The assistant only talks to the first one.

## Assistant to mcp.lunacal.ai

The live metadata document `https://mcp.lunacal.ai/.well-known/oauth-authorization-server` currently says:

| Setting | Value |
| --- | --- |
| Issuer | `https://mcp.lunacal.ai` |
| Authorization endpoint | `https://mcp.lunacal.ai/authorize` |
| Token endpoint | `https://mcp.lunacal.ai/token` |
| Registration endpoint | `https://mcp.lunacal.ai/register` |
| Grant types | `authorization_code`, `refresh_token` |
| PKCE | `S256` only |
| Token endpoint client authentication | `none` |
| Protected resource | `https://mcp.lunacal.ai/mcp` |
| Bearer | `Authorization` header |

Clients register themselves. Lunacal does not hand you a client id for Claude or ChatGPT. You do not create an API key for this.

## mcp.lunacal.ai to Lunacal

The MCP server is one pre-registered OAuth client of the Lunacal app. Its client secret stays on Lunacal's servers. These routes are not for your integration. They are here so a review can see what the consent click actually does.

<Steps>
  <Step title="Sign in, if needed">
    The browser opens `/auth/platform/authorize` with the MCP server's `redirect_uri`. If there is no Lunacal session, Lunacal sends the user through login and back to that URL.
  </Step>
  <Step title="Plan check">
    The account must have the MCP feature (Tier 4, or a per-user override). Otherwise Lunacal redirects to `/new-settings?tabName=general&upgrade=mcp` and does not mint a code.
  </Step>
  <Step title="Consent">
    The page lists the permissions stored on that OAuth client. Each group is Event types, Bookings, Schedules, Apps, or Profile, marked Read, Write, or both. The page does not offer a per-tool picker. The user chooses **Allow** or **Go back**.
  </Step>
  <Step title="Grant">
    **Allow** POSTs to `/api/mcp/authorize` with `redirect_uri`, optional `state`, and a CSRF token. The token must match an `HttpOnly`, `SameSite=Strict` cookie set when the page rendered. The cookie lives for 10 minutes and is cleared when the grant is accepted. A missing or mismatched token returns `403` `Invalid or expired consent request`. `redirect_uri` must be on the client's registered list.
  </Step>
  <Step title="Code and tokens">
    Lunacal creates a one-time authorization code and redirects to the MCP server with `code` and `state`. The MCP server exchanges that code at `/api/mcp/token`. The code is deleted when it is used. A code older than 10 minutes is deleted and rejected as `Code expired`.
  </Step>
</Steps>

Access tokens last **1 hour**. Refresh tokens last **365 days**. Refresh deletes the refresh token it just accepted and issues a new pair. Replaying a refresh token fails with `Invalid refresh token`. An expired refresh token is deleted and fails with `Refresh token expired`.

API keys from **Settings → Developer** are a different credential. They start with `lunacal_` and are documented under [API key authentication](/api/authentication). An assistant should not ask the user to paste one.

## What the tools can do

Every tool runs as the user who clicked **Allow**. There is no second, narrower key.

| Tool | Access | Side effect |
| --- | --- | --- |
| `get_my_profile` | Read | None |
| `find_available_slots` | Read | None |
| `list_bookings` | Read | None. Results include attendee names and emails. |
| `list_event_types` | Read | None |
| `get_event_type` | Read | None |
| `create_booking` | Write | Creates a booking and can email the attendee |
| `reschedule_booking` | Write | Moves a booking and can email the attendee |
| `cancel_booking` | Write, destructive | Cancels a booking and can email the attendee. Not reversible |
| `create_event_type` | Write | Adds an event type |
| `update_event_type` | Write | Changes that event type for later bookings |
| `set_event_type_published` | Write | Shows or hides the event type on the public booking page |

Lunacal does not currently offer a read-only OAuth client for this server. To limit damage, leave tool confirmation on in the AI client, or disable the write tools there if the client allows it.

## Errors the client should expect

| Situation | Result |
| --- | --- |
| Missing or expired access token on a Lunacal API route | HTTP `401`. The MCP server should refresh or send the user through consent again. |
| MCP feature missing at consent time | Redirect to settings. No code is issued. |
| Bad CSRF or unregistered `redirect_uri` | `403` or `400`. No code is issued. |
| Unknown booking or event type | Tool error. Look the id up again. |
| Slot no longer free | Tool error. Fetch slots again. |
| Lunacal `500` | Retry a read. Before retrying a write, list the resource. The first call may have landed. |

## Revoking access

Remove the Lunacal connector in the AI client. That stops the client from using its refresh token. Access tokens already issued keep working until they expire, which is at most one hour.

Deleting an API key in Developer settings does not disconnect MCP. They are different records.
