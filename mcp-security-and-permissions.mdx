Use this page when you want to know what a connected assistant can do in Lunacal, or when you are deciding whether your team should turn the connection on.

The setup steps for Claude are on [Connect Lunacal to Claude](/mcp-server).

## What you approve

The first time an assistant uses Lunacal, your browser opens a Lunacal page.

<Steps>
  <Step title="Sign in, if you are not already">
    If there is no Lunacal session, you sign in and return to the same page.
  </Step>
  <Step title="Confirm the account can connect">
    The account needs Tier 4, or MCP access turned on for that user. Otherwise Lunacal sends you to Settings and does not connect.
  </Step>
  <Step title="Read the permissions and choose Allow">
    The page lists what the connection can read and change. The groups are event types, bookings, schedules, apps, and profile. Each one is marked Read, Write, or both. There is no switch for a single action. Click **Allow** to continue, or **Go back** to stop.
  </Step>
</Steps>

**Allow** is tied to that page. Lunacal checks a short-lived cookie from the same visit, and it only redirects back to an address it already has on file for the Lunacal connection. A link from another site cannot press **Allow** for you.

You do not create an API key for this, and you do not receive a client id. The assistant signs in through Lunacal's hosted connection at `https://mcp.lunacal.ai/mcp`.

## How long the connection lasts

| | |
| --- | --- |
| Access token | 1 hour. The assistant refreshes it without asking you. |
| Refresh token | 365 days. Each refresh replaces it. An old refresh token cannot be used again. |
| Sign-in code | 10 minutes, and only once. |

If a refresh is rejected, disconnect Lunacal in the assistant and sign in again.

## What each action can change

Everything runs as the Lunacal user who clicked **Allow**.

| Action | Changes your account? | What to know |
| --- | --- | --- |
| See the connected profile | No | Name, email, username, timezone |
| Find open times | No | |
| List bookings | No | Includes attendee names and email addresses |
| List or open an event type | No | |
| Book a meeting | Yes | Can email the attendee |
| Move a meeting | Yes | Can email the attendee |
| Cancel a meeting | Yes | Cannot be undone. Can email the attendee |
| Create or edit an event type | Yes | Applies to later bookings |
| Publish or unpublish an event type | Yes | Shows or hides it on the public booking page |

Lunacal does not offer a read-only connection today. Leave confirmation on in the assistant, and decline any action whose details look wrong. If the assistant lets you disable individual tools, turn off the ones that book, cancel, or edit.

## Disconnect

Remove Lunacal from the assistant's connectors. That stops new use of the connection. An access token that was already issued keeps working until it expires, which is at most one hour.

Deleting an API key under **Settings → Developer** does not disconnect the assistant. Keys and this sign-in are separate.

## For a security review

The assistant talks only to `mcp.lunacal.ai`. That server is one registered client of Lunacal. Its client secret stays on Lunacal's servers.

| Setting | Value |
| --- | --- |
| MCP endpoint | `https://mcp.lunacal.ai/mcp` |
| Authorization | `https://mcp.lunacal.ai/authorize` |
| Token | `https://mcp.lunacal.ai/token` |
| Client registration | `https://mcp.lunacal.ai/register` |
| Grants | Authorization code, and refresh |
| PKCE | S256 |
| Client authentication | None. The assistant is a public client. |
| Credential header | `Authorization: Bearer` |

The consent form posts to `/api/mcp/authorize`. The one-time code is exchanged at `/api/mcp/token`. Those two routes are for the Lunacal connection, not for your own integration. Your own integration uses an [API key](/api/authentication).
