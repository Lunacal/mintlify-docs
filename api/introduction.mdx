Use the Lunacal API when you want your own app, script, or automation to act on a Lunacal account: look up the user, read open times, and create or change bookings and event types.

Every call runs as the person who owns the API key. The key does not have separate permissions. If that person can do it in Lunacal, the key can do it through these routes.

AI assistants such as Claude do not use this key. They connect through [MCP](/mcp-server) and ask the user to sign in.

## Before you start

<Info>
  Agency client accounts do not see the Developer tab.
</Info>

1. Sign in to Lunacal.
2. Open [Settings → Developer](https://app.lunacal.ai/new-settings?tabName=developer).
3. Create a key and store it somewhere only your server can read. The steps are on [Create and use an API key](/api/authentication).

## How a request is shaped

| | |
| --- | --- |
| Base URL | `https://app.lunacal.ai` |
| Method | `POST` for every route on this page |
| Header | `Authorization: Bearer lunacal_<your-key>` |
| Body | JSON, with `Content-Type: application/json` |

A successful call returns the result as JSON. A failed call returns JSON with a `message` field. The status codes are explained on [Errors](/api/errors).

Keep the key in an environment variable named `LUNACAL_API_KEY`. The examples on these pages use that name.

## What you can call

| You want to | Route |
| --- | --- |
| See who the key belongs to | [`POST /api/user/me`](/api/endpoints/me) |
| Find open times | [`POST /api/availability`](/api/endpoints/get-availability) |
| List bookings | [`POST /api/bookings/list`](/api/endpoints/bookings-list) |
| Book or reschedule | [`POST /api/bookings/create`](/api/endpoints/bookings-create) |
| Cancel a booking | [`POST /api/bookings/cancel`](/api/endpoints/bookings-cancel) |
| List event types | [`POST /api/event-types/list`](/api/endpoints/event-types-list) |
| Read one event type | [`POST /api/event-types/get`](/api/endpoints/event-types-get) |
| Create an event type | [`POST /api/event-types/create`](/api/endpoints/event-types-create) |
| Update an event type | [`POST /api/event-types/update`](/api/endpoints/event-types-update) |
| Delete an event type | [`POST /api/event-types/delete`](/api/endpoints/event-types-delete) |
| Show or hide an event type | [`POST /api/event-types/switch-published`](/api/endpoints/event-types-switch-published) |

## Try it

This call returns the profile of the key's owner. You need `id`, `email`, `username`, and `timeZone` for almost every other call. The response also includes plan and branding fields that the Lunacal app uses. Rely on the four fields above.

<CodeGroup>

```bash cURL
curl -X POST https://app.lunacal.ai/api/user/me \
  -H "Authorization: Bearer $LUNACAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

```javascript JavaScript
const response = await fetch("https://app.lunacal.ai/api/user/me", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.LUNACAL_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({}),
});

if (!response.ok) {
  const error = await response.json();
  throw new Error(`${response.status} ${error.message}`);
}

const me = await response.json();
console.log(me.id, me.email, me.timeZone);
```

</CodeGroup>
